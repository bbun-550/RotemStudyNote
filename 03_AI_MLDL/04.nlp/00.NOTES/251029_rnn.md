
# 📘 RNN 기반 텍스트 분류·생성 실습에서 새롭게 등장한 이론 정리

## 1. Tokenizer 기반 텍스트 수치화의 내부 동작 이해

`rnn03_sigmoid.ipynb` **Tokenizer를 단순 도구가 아니라, NLP 파이프라인의 핵심 컴포넌트**로 다룬다.
### 1-1. Tokenizer가 생성하는 내부 정보

```python
tokenizer.fit_on_texts(texts)
```

이 한 줄로 다음 정보가 내부적으로 생성된다.

- word_index    
    → 단어 → 정수 인덱스 매핑    
- index_word    
    → 정수 인덱스 → 단어 역매핑    
- word_counts    
    → 단어별 등장 빈도    
- word_docs    
    → 해당 단어가 등장한 문서 수    
- document_count    
    → 전체 문서 수    

👉 토큰화 개념
\
👉 [NLP 기본 이론 정리](251027_nlp.md)


**새롭게 중요한 관점**
> Tokenizer는 단순 전처리기가 아니라
> **어휘 집합(Vocabulary) + 통계 정보까지 포함한 상태 객체(Stateful Object)** 이다.

## 2. Padding 전략이 모델 의미에 미치는 영향

rnn03 ~ rnn05에서 모두 `pad_sequences()`가 사용되지만,
이 시점부터는 **padding이 단순한 길이 맞춤이 아님**을 체감한다.

### 2-1. `padding=‘pre’` 를 사용하는 이유

```python
pad_sequences(sequences, maxlen, padding='pre')
```

- 중요한 정보(최근 단어)가 **시퀀스 뒤쪽**에 위치    
- LSTM이 마지막 시점의 정보를 더 강하게 반영    
- 텍스트 생성/분류 모두에 유리    

### 2-2. Embedding + mask_zero=True 의 의미

```python
Embedding(vocab_size, dim, mask_zero=True)
```

- padding으로 들어간 0을 **모델이 자동으로 무시**    
- RNN이 의미 없는 패딩 시점을 학습하지 않음    
- **시퀀스 안정성, 수렴 속도, 성능**에 직접적인 영향    

> padding은 데이터 문제이지만
> mask_zero는 **모델 설계 문제**라는 점이 새롭게 등장한 관점이다.

## 3. Sigmoid vs Softmax : 출력층 선택이 문제 정의다

rnn03과 rnn04의 가장 핵심적인 차이는
**출력층의 활성화 함수가 아니라, 문제 정의 자체**다.

### 3-1. Sigmoid 출력 (rnn03_sigmoid.ipynb)

```python
Dense(1, activation='sigmoid')
loss = binary_crossentropy
```

- 출력: 단일 확률값 (0~1)    
- 의미: 특정 클래스일 확률    
- 문제 유형: **이진 분류**    
- 판단 기준은 사람이 정함 (예: 0.5)    

### 3-2. Softmax 출력 (rnn04, rnn05)

```python
Dense(vocab_size, activation='softmax')
loss = categorical_crossentropy
```

- 출력: vocab 전체에 대한 확률 분포    
- 의미: “다음에 올 단어는 무엇인가?”    
- 문제 유형: **다항 분류**    
- 확률 분포 자체가 모델의 결과    

👉 기본적인 분류 이론
\
👉 [NLP 기본 이론 정리](251027_nlp.md)

**새롭게 등장한 관점**
> Softmax 기반 언어 모델에서
> **출력은 ‘정답’이 아니라 ‘다음 선택지의 분포’** 이다.

## 4. Language Model 관점: 입력과 정답을 어떻게 만드는가

rnn04 ~ rnn05에서 처음으로
**“모델이 무엇을 예측하도록 학습되는지”를 데이터 단계에서 직접 설계**한다.

### 4-1. Next-Token Prediction 구조

하나의 문장을 여러 학습 샘플로 분해:

```yaml
"I love NLP"
→ [I] → love
→ [I, love] → NLP
```

- 입력(X): 이전 단어 시퀀스
- 정답(y): 바로 다음 단어

이 구조는 곧,
> **언어 모델(Language Model)의 정의 그 자체**

---

## 5. Auto-regressive Text Generation (자기회귀 생성)

rnn04, rnn05에서 구현한 문장 생성 방식은 모두 동일한 원리다.

### **5-1. Auto-regressive 생성 흐름**

1. 시작 단어(seed) 입력    
2. 다음 단어 확률 예측 (Softmax)    
3. 가장 높은 확률 단어 선택 (argmax)    
4. 선택된 단어를 다시 입력에 추가    
5. 반복    

```yaml
입력 → 예측 → 입력 → 예측 → …
```

**중요한 인식 변화**

> 모델은 문장을 “이해해서” 만드는 것이 아니라
> **이전까지의 단어를 조건으로 가장 그럴듯한 다음 토큰을 고르는 것**이다.

## 6. 데이터 규모가 모델 성능을 결정하는 방식

rnn05에서 처음으로 **데이터 규모의 영향**을 명확히 체감한다.

- vocab_size ≈ 3,500  
- 학습 샘플 수 급증 (문장 → 다수 시퀀스)    
- 학습 시간 증가    
- 문법은 그럴듯하지만 의미는 불완전    

**이 시점에서 자연스럽게 등장하는 질문**
> “왜 GPT는 이렇게 자연스러운데,
> 나는 이 정도에서 멈추는가?”

→ **Attention / Transformer / 대규모 Pretraining**으로 이어지는 흐름의 출발점
