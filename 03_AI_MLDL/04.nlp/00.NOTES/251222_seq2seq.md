# 📘 Sequence-to-Sequence (Seq2Seq) 모델 이론 정리

_(Encoder–Decoder 구조의 등장 배경과 한계)_

---

## 1. Seq2Seq란 무엇인가?

**Seq2Seq (Sequence-to-Sequence)** 모델은
**입력 시퀀스를 받아 출력 시퀀스로 변환**하는 신경망 구조다.

- 입력과 출력의 길이가 **서로 달라도 처리 가능**    
- 대표적인 적용 분야:
    - 기계 번역 (번역)
    - 요약
    - 질의응답
    - 대화 모델  

예시:
```yaml
입력:  I have a pen
출력:  나는 펜을 갖고 있다
```

👉 단순 분류나 다음 값 예측을 넘어
>**“시퀀스 → 시퀀스 변환”** 문제를 처음으로 일반화한 구조

---

## 2. Seq2Seq 등장 배경

기존 RNN/LSTM 모델의 한계:
- many-to-one: 문장 분류    
- many-to-many: 다음 토큰 예측    
- ❌ **입력 시퀀스를 통째로 변환하는 구조 부재**    

특히 번역 문제에서는:
- 입력 길이 ≠ 출력 길이    
- 입력 전체 의미를 고려해야 함    

👉 이 요구를 만족하기 위해 **Encoder–Decoder 구조** 등장

---

## 3. Seq2Seq의 기본 구조 (Encoder–Decoder)

Seq2Seq는 **두 개의 RNN 계열 네트워크**로 구성된다.
```yaml
입력 시퀀스 → Encoder → Context Vector → Decoder → 출력 시퀀스
```

### Encoder

- 입력 문장을 순차적으로 읽음
- 마지막 시점의 hidden state를 **요약 벡터**로 생성
- 이 벡터를 **Context Vector**라고 부름
###  Decoder

- Context Vector를 초기 상태로 받아    
- 출력 시퀀스를 한 토큰씩 생성    
- 이전 출력이 다음 입력으로 사용됨 (auto-regressive)    


📌 Encoder와 Decoder는 보통 **LSTM 또는 GRU** 사용

\
👉 [RNN & LSTM 구조 이해](251028_rnn.md)

## 4. Context Vector의 의미

  **Context Vector**는:
- 입력 시퀀스 전체를 하나의 벡터로 압축한 표현
- Encoder의 마지막 hidden state

개념적으로는:
> “입력 문장의 모든 의미를 하나의 벡터에 담아 Decoder에게 전달”

하지만 여기서 **치명적인 문제가 발생**

---

## 5. Seq2Seq의 한계: Context Vector 병목 (Bottleneck)

### ❗ 문제 1: 정보 압축 한계

- 긴 문장일수록:    
    - 모든 정보를 **고정 길이 벡터 하나**에 담기 어려움
- 문장이 길어질수록 번역 품질 급격히 저하 

### ❗ 문제 2: 장기 의존성 문제

- Encoder 초반 입력 정보가    
- Decoder까지 제대로 전달되지 않음    
- 특히 문장 앞부분 정보 손실 심각    

👉 이 문제는 RNN 자체의 한계와도 연결됨
\

## 6. Seq2Seq + Teacher Forcing

훈련 시 Decoder는 보통 **Teacher Forcing**을 사용한다.
### Teacher Forcing이란?

- 이전 시점의 **모델 예측값**이 아니라    
- **정답 토큰**을 다음 입력으로 사용
  
장점:
- 학습 속도 향상    
- 안정적인 수렴    

단점:
- 추론(inference) 시에는 정답이 없으므로    
- 학습–추론 간 괴리(exposure bias) 발생    

---

## 7. Seq2Seq → Attention으로의 연결

Seq2Seq의 핵심 한계는 단 하나:
> **“모든 정보를 하나의 Context Vector에 몰아넣는 구조”**

이를 해결하기 위해 등장한 개념이 바로 **Attention**.

### **Attention의 핵심 아이디어**

- Decoder가 매 시점마다    
- **입력 전체를 다시 참고**    
- “지금 이 출력에 중요한 입력은 무엇인가?”를 직접 계산    

> Context Vector를 **고정값 → 동적 값**으로 확장

## 8. Seq2Seq의 위치/흐름 정리 

```yaml
RNN / LSTM
   ↓
Seq2Seq (Encoder–Decoder)
   ↓
Attention
   ↓
Transformer
```

Seq2Seq는:
- RNN의 **응용 구조**    
- Attention의 **직접적인 등장 배경**    
- Transformer로 가기 전 **필수 중간 단계**

## 9. 요약 정리

|**항목**|**Seq2Seq**|
|---|---|
|목적|시퀀스 → 시퀀스 변환|
|구조|Encoder + Decoder|
|핵심 전달|Context Vector|
|장점|길이가 다른 입력/출력 처리|
|한계|Context Vector 병목|
|해결책|Attention|

---


> **Seq2Seq의 본질**

```
입력 시퀀스
   ↓
Encoder (RNN/LSTM)
   ↓   ← (state 전달)
Decoder (RNN/LSTM)
   ↓
출력 시퀀스
```

✔ Encoder는 **입력 전체를 읽고 요약(state)**
✔ Decoder는 **그 요약을 기반으로 출력 시퀀스를 생성**

> **“Encoder를 통과한 정보(state)가 Decoder로 넘어가서 출력이 나온다”**

  
## return_state=True
### 📌 기본 개념
LSTM은 내부적으로 **두 가지 상태**를 가진다:

|**이름**|**기호**|**의미**|
|---|---|---|
|Hidden state|h_t|현재 시점의 출력/요약|
|Cell state|c_t|장기 기억 저장소|

### 📌 기본 LSTM (return_state=False)

```yaml
output = LSTM(units)(input)
```

이때 반환되는 것은:

```yaml
output = h_t   (마지막 시점 hidden state)
```

❌ c_t는 **밖으로 안 나옴**
❌ Encoder–Decoder 연결 불가

### 📌 return_state=True

```yaml
output, h, c = LSTM(units, return_state=True)(input)
```

이제 반환값은:

```yaml
output → 마지막 시점 출력
h → 마지막 hidden state
c → 마지막 cell state
```

### 🔥 Seq2Seq에서 왜 중요?

Encoder는:
- 입력 전체를 읽고
- **최종 상태(h, c)를 Decoder에게 넘겨야 함**
    
```python
encoder_states = [h, c]
```

그리고 Decoder에서:

```python
decoder_lstm(..., initial_state=encoder_states)
```


> `return_state=True`
> → Encoder가 Decoder에게 “기억(state)”를 넘겨주기 위한 필수 옵션

---

## return_sequences=True 는 무엇인가?
  

### 📌 기본 LSTM 출력 구조

LSTM은 원래 **시퀀스 처리 모델**이지만 기본 설정에서는 **마지막 결과만 반환**한다.

```yaml
output = LSTM(units)(input)
```

결과:
```yaml
(batch_size, units)
```

→ **many-to-one 구조**
### 📌 return_sequences=True

```python
output = LSTM(units, return_sequences=True)(input)
```

결과:
```python
(batch_size, time_steps, units)
```

→ **모든 시점의 출력** 반환

### 📌 Seq2Seq Decoder에서 왜 필요할까?

Decoder는:
- 한 번에 한 단어가 아니라    
- **출력 시퀀스 전체**를 만들어야 함    

```yaml
나는 → 펜을 → 갖고 → 있다
```

즉, Decoder는 **many-to-many 구조**

그래서 반드시:
```python
decoder_lstm = LSTM(
    units,
    return_sequences=True,  # 출력 시퀀스 유지
    return_state=True       # 다음 스텝 상태 전달
)
```

---

## 옵션별 역할 한 줄 요약

|**옵션**|**의미**|**Seq2Seq에서 역할**|
|---|---|---|
|return_state=True|내부 상태(h, c) 반환|Encoder → Decoder 상태 전달|
|return_sequences=True|모든 시점 출력|Decoder의 출력 시퀀스 생성|

---

## Encoder / Decoder 기준으로 정리하면

### **✔ Encoder LSTM**

```python
LSTM(units, return_state=True)
```

- 출력 시퀀스 ❌    
- 마지막 상태 ⭕    
- 목적: **입력 요약**

### ✔ Decoder LSTM

```python
LSTM(units, return_sequences=True, return_state=True)
```

- 출력 시퀀스 ⭕    
- 상태 전달 ⭕    
- 목적: **문장 생성**
