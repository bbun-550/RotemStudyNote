# 코사인 유사도

## 1️⃣ sim(query, doc)는 보통 무엇인가?

**✅ 대부분의 RAG 시스템에서** 아래 수식 사용

```
sim(query, doc) = 코사인 유사도 (cosine similarity)
```

- LangChain
- Chroma / FAISS
- HuggingFace 임베딩 기반 retriever
👉 **기본값 = 코사인 유사도**
(명시하지 않아도 내부적으로 cosine을 쓰는 경우가 거의 90% 이상)

---

## 2️⃣ 왜 코사인 유사도를 쓰는가? (직관)
 **핵심 아이디어**

> **문장의 길이는 중요하지 않고, 의미의 방향이 중요하다**

임베딩 벡터는 보통 이렇게 생김:
```
문장 → [0.12, -0.87, 0.44, ..., 0.03]  (768차원 같은 벡터)
```
이때 중요한 건:
- 벡터의 **크기(length)** ❌
- 벡터의 **방향(direction)** ⭕
👉 코사인 유사도는
**“두 벡터가 얼마나 같은 방향을 보고 있나?”** 를 재는 방식

---
## 3️⃣  코사인 유사도 비유 설명
**🎯 비유: 손가락 방향**
- 너의 손가락 → 질문
- 친구의 손가락 → 문서

|**상황**|**의미**|
|---|---|
|같은 방향|의미가 매우 비슷|
|약간 비슷|어느 정도 관련|
|반대 방향|의미가 다름|

👉 손가락 **길이**는 상관 없음
👉 **방향만 중요**

---

## 4️⃣ 수식으로 보면...

**📐 수식**
```
cosine_similarity(A, B) = (A · B) / (||A|| × ||B||)
```
**각각 무슨 뜻이냐면**
**🔹 A · B (내적, dot product)**
- 두 벡터가 얼마나 같은 방향으로 뻗어 있는지
**🔹 ||A||, ||B|| (벡터 크기)**
- 벡터의 길이 (정규화용)
👉 전체 의미:

> “길이 영향은 제거하고 방향만 비교하자”
---

## 5️⃣ 값의 범위 (아주 중요)

|**코사인 값**|**의미**|
|---|---|
|**1.0**|완전히 같은 의미|
|**0.7 ~ 0.9**|매우 유사|
|**0.3 ~ 0.6**|어느 정도 관련|
|**0.0**|거의 무관|
|**-1.0**|정반대 의미|

📌 RAG에서는 보통

- **0.6 이상** → 관련 있음
- **0.8 이상** → 강한 근거 문서
    

---

## 6️⃣ 예시로 이해해보자
**질문**

> “삼성에스디에스 장점 알려줘”

**문서 A**
> “삼성에스디에스는 복지와 워라밸이 좋다”
→ cosine ≈ **0.85**

**문서 B**
> “삼성전자 반도체 공정 기술”
→ cosine ≈ **0.30**

**문서 C**
> “SDS 연봉과 프로젝트 경험”
→ cosine ≈ **0.78**

👉 retriever는 A, C를 먼저 고른다.

---

## 7️⃣ 그럼 다른 유사도는 안 쓰나?

  
쓴다. 하지만 **RAG에서는 거의 안 씀**.
**🔹 1️⃣ 유클리드 거리 (Euclidean)**
```
√((x1−y1)² + (x2−y2)² + ...)
```

❌ 문제점:
- 벡터 크기에 민감
- 문장 길이에 영향 받음
👉 **임베딩에는 부적합**

---

**🔹 2️⃣ 내적 (Dot Product)**
```
A · B
```

- 빠름
- 하지만 벡터 크기 영향 큼

📌 **FAISS에서 종종 사용**

(단, 보통 사전에 정규화함)

---

**🔹 3️⃣ Jaccard / TF-IDF**
- 단어 겹침 기반
- 의미 이해 ❌

👉 **LLM/RAG 시대에는 거의 사용 안 함**

---

## 8️⃣ MMR 수식에서 다시 보면

```
MMR = λ · sim(query, doc) − (1 − λ) · max(sim(doc, selected_docs))
```

여기서 sim()은:

> **“임베딩 벡터 간 코사인 유사도”**

- query ↔ doc
- doc ↔ doc
👉 그래서 MMR이 **의미 기반 중복 제거**가 가능한 것

---

## 9️⃣ 정리

> “MMR에서 사용하는 sim(query, doc)는
> 임베딩 벡터 간 코사인 유사도이며,
> 문장의 길이가 아닌 의미적 방향의 유사성을 기준으로
> 문서를 선택합니다.”
