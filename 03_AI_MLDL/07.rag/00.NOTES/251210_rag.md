## 1. PDF 기반 RAG의 구조적 특징 - rag06

**PDF 문서를 지식 소스로 사용하는 RAG 구조** 등장

### 1-1. PDF Loader의 역할 변화

PDF RAG에서 Loader는 단순 텍스트 로더가 아니라 다음 책임을 가진다.

- 페이지 단위 문서 분리
- 메타데이터(page, source, file_path) 자동 생성
- 후속 Chunking 전략의 기준 제공

> 텍스트 기반 RAG와 달리  
> **PDF는 페이지 단위라는 물리적 구조를 가진 문서**라는 점이 핵심 차이점이다.

---

### 1-2. 페이지 단위 문맥 단절 문제

PDF를 페이지 단위로 처리하면 다음 문제가 발생한다.

- 문장이 페이지 경계를 넘어갈 경우 의미 단절
- Retrieval 결과가 “앞뒤 맥락 없이” 반환됨
- LLM이 질문의 주어·대상을 잃어버림

➡️ 이 문제를 해결하기 위한 핵심 전략이 **Overlap Chunking**이다.

## 2. 비정형 문서(PDF) 전처리 이론 - rag07

**PDF 내부의 비정형 텍스트 처리 문제** 등장

### 2-1. PDF 텍스트의 비정형성

PDF 문서는 다음 특성을 가진다.

- 줄바꿈 기준이 의미 단위가 아님
- 표(Table), 제목, 본문이 섞여 있음
- 공백, 특수문자, 페이지 번호가 노이즈로 포함

따라서 rag07에서는 다음 전처리 전략을 사용한다.

- 정규표현식 기반 불필요 문자 제거
- 한글/텍스트 필터링
- 여러 줄을 하나의 긴 문맥 문자열로 병합

> 핵심은 “완벽한 정제”가 아니라  
> **Embedding 가능한 최소 품질 확보**이다.

---

### 2-2. 표(Table) 데이터 분리 전략

PDF 내 표는 일반 텍스트 RAG와 **전혀 다른 성격**을 가진다.

rag07에서의 핵심 개념:

- 표 데이터는 “자연어 문서”가 아니라 **구조화 데이터**
- RAG 이전 단계에서 DataFrame으로 분리
- CSV / Excel 저장 → 통계·분석·검색 용도 분리

➡️ 이 단계는  
**RAG + Data Analytics 분기점**에 해당한다.

## 3. VectorDB 입력 단위 설계 이론 - rag08

“무엇을 하나의 문서로 저장할 것인가?”라는 문제가 등장

### 3-1. 문단(Document) vs 페이지(Document)

VectorDB에 저장할 단위는 다음 중 선택해야 한다.

| 단위 | 장점 | 단점 |
|---|---|---|
| 페이지 | 문맥 유지 | 검색 정밀도 낮음 |
| 문단 | 검색 정확도 ↑ | 문맥 단절 위험 |

rag08의 결론은 다음과 같다.

> **문단 단위 + 페이지 간 overlap**이 가장 균형 잡힌 전략

이 개념은 이후 **Routing RAG / Agent RAG**의 기초가 된다.

## 4. rag09 — Retrieval 결과 해석 관점 확장

Retrieval 결과를 **“그대로 쓰지 않는다”**는 개념 등장

### 4-1. Distance / Score 기반 해석

VectorDB 검색 결과에는 다음 정보가 포함된다.

- 문서 텍스트
- 거리(distance) 또는 유사도(score)

이 값은 다음 판단에 사용된다.

- 검색 결과 신뢰도 판단
- Top-K 중 일부만 사용
- Threshold 기반 필터링

## 5. Router 기반 RAG 아키텍처 이론 - rag10

**단일 RAG를 넘어선 구조적 전환점**.

### 5-1. 왜 Routing RAG가 필요한가?

모든 질문을 동일한 RAG 체인으로 처리하면 다음 문제가 발생한다.

- 간단한 질문에도 VectorDB 검색 수행
- 코드/개념 질문에 불필요한 문서 검색
- 비용, 응답 시간 증가

➡️ 해결책: **질문 유형 분기(Routing)**

---

### 5-2. Router의 역할

Router는 질문을 다음 중 하나로 분류한다.

- RAG Chain (문서 기반 질문)
- Code / Logic Chain
- General LLM Chain

즉, Router는 **LLM Orchestration 계층**이다.

```text
User Query
   ↓
[ Router ]
   ├─ RAG Chain
   ├─ Code Chain
   └─ General Chain
