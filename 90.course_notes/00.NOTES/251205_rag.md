## 1. 텍스트 기반 RAG의 구조적 특징

RAG(Retrieval-Augmented Generation) 파이프라인은 다음 단계로 구성된다.

1) Document Loading
2) Text Splitting (Chunking)
3) Embedding (문서 → 벡터)
4) VectorDB 저장 (ChromaDB)
5) Retrieval (유사도 기반 검색)
6) Prompt Augmentation (증강)
7) LLM Generation

7단계를 직접 구현하는 가장 기초적인 RAG 버전

---

## 2 . 텍스트 로딩 & 분리(Text Loading & Chunking)

✦ 2-1. TextLoader (LangChain)
	•	LangChain의 TextLoader를 사용하여 .txt 파일을 Document 객체로 불러온다.
	•	문서 전체를 하나의 큰 문자열로 처리하는 방식이다.

✦ 2-2. CharacterTextSplitter
	•	긴 문서를 LLM이 사용할 수 있도록 조각(chunk) 으로 나누는 기능.
	•	rag02에서는 줄 단위(\n) 문장 분리 전략을 사용.

Chunking 목적:
	•	LLM이 과도하게 긴 문서를 처리하지 않음
	•	VectorDB 검색 시 문장 단위로 의미 기반 검색이 가능해짐

---

## 3. Embedding — 텍스트를 벡터로 바꾸는 과정

3-1. Embedding이란?

Embedding은 문장·문서의 의미를 고차원 벡터로 변환하는 과정이다.
	•	입력: 텍스트
	•	출력: 숫자 벡터 (예: 384차원, 768차원 등)

벡터 공간에서 의미적으로 비슷한 문장끼리 가까운 위치에 있게 된다.

→ Retrieval에서 “가장 의미가 가까운 문서”를 찾기 위한 기반 기술

rag02.ipynb 사용 모델
	•	all-MiniLM-L6-v2
	•	빠르고 가볍지만 높은 성능
	•	실전 RAG에서 가장 많이 사용되는 상용급 SentenceTransformer 모델

## 4. VectorDB — ChromaDB vs FAISS

rag02.ipynb에서는 ChromaDB를 사용하지만, FAISS도 존재한다.

### 🟩 ChromaDB (Vector + 메타데이터 + 영구저장까지 다 되는 DB 시스템)

특징
	•	벡터, 원문 문서, 메타데이터, id를 모두 한 구조에서 관리
	•	persist_directory를 사용하면 디스크 기반 DB 생성 가능
	•	LangChain과 가장 높은 호환성
	•	사용 난이도 낮음 (RAG 입문/프로덕션 모두 적합)

한줄 요약

> “RAG 프로젝트를 바로 시작할 수 있게 모든 것을 갖춘 벡터 데이터베이스”

Python 사용 예시
```python
client = chromadb.Client()
collection = client.create_collection("reviews")

collection.add(
    ids=["1"],
    documents=["복지가 좋은 회사입니다."],
    embeddings=[vector],
    metadatas=[{"company": "A"}]
)
```

### 🟦 FAISS (Facebook AI의 초고속 벡터 검색 엔진)

특징
	•	벡터 자체만 빠르게 검색하는 데 초점
	•	메타데이터 저장 X → 직접 구현해야 함
	•	디스크 저장 X → 따로 파일 저장 구현 필요
	•	초대규모 벡터 검색에 뛰어남 (수백만~수억 벡터)

한줄 요약

>“벡터 검색 알고리즘 자체를 실험하거나 매우 큰 데이터에서 성능을 원할 때 사용”

Python 예시
```python
index = faiss.IndexFlatL2(768)
index.add(embs)
distances, indices = index.search(q_emb, k=5)
```

▶ 언제 무엇을 선택해야 할까?

| 상황                          | 추천       |
| --------------------------- | -------- |
| RAG 프로젝트                    | ChromaDB |
| LangChain, LlamaIndex 연동    | ChromaDB |
| 문서 + 벡터 + 메타데이터 함께 저장해야 할 때 | ChromaDB |
| 초대규모(1M~1B) 벡터 검색           | FAISS    |
| 벡터 검색 알고리즘 연구/튜닝            | FAISS    |
| 메타데이터 저장을 별도로 관리해도 될 때      | FAISS    |

## 5. Retrieval — 유사도 기반 문서 검색

Embedding된 쿼리(query)를 VectorDB에서 검색하여
가장 의미적으로 가까운 문장을 반환한다.

rag02에서는 다음 기술을 사용한다:

• Cosine Distance
	•	벡터 간 각도(유사도)를 비교하는 방식
	•	거리(distance)가 낮을수록 유사

• Dot Product (유사도 계산)

직접 구현해보며 vector similarity 개념을 체득한다.

---
## 6. Prompt Augmentation — 검색된 문서를 기반으로 답변 품질 강화

검색된 문서를 다음과 같이 프롬프트에 삽입한다.

```python
너는 한국 전통 음식 전문가야.
아래 문서를 참고하여 질문에 답해줘:

{검색된 문서들}

질문: {query}
```
이때 LLM은 외부 문서(임베딩 기반 검색 결과)를 바탕으로
더 신뢰도 높은 답변을 제공하게 된다.

## 8. rag02가 RAG 전체 과정에서 갖는 의미

rag02는 가장 기본적인 RAG 골격을 직접 구현하는 단계이며,
이후 rag03~rag11의 실습(웹·PDF·이미지·스트리밍 RAG)으로 확장되는 기반이 된다.

특히 아래 개념을 실체로 이해하게 하는 실습이다:

	•	Embedding 모델의 중요성
	•	Chunking 전략이 검색 품질에 미치는 영향
	•	VectorDB의 검색 메커니즘
	•	Retrieval → Augmentation → Generation 전체 플로우 조립
