## 🧩 2. VectorDB 내부 조회 이론 (Get / Count / ID-Based Retrieval)

rag03에서는 다음 코드가 등장합니다:

```python
collection.get()
collection.count()
collection.get(ids=["doc_0"])
```

이것을 통해 VectorDB의 내부 저장 구조를 직접 확인할 수 있습니다.

✔ 2-1. collection.get() — 저장된 전체 문서 확인

ChromaDB의 get() 결과 구조

```python
{
  "ids": ["doc_0", "doc_1", ...],
  "documents": ["문서1", "문서2", ...],
  "embeddings": [[벡터1], [벡터2], ...],
  "metadatas": [...]
}
```

→ rag02에서는 검색(query)만 했지만, rag03은 VectorDB의 전체 구조를 직접 조회하여 검증하는 과정이 추가됨.

학습 포인트

	•	RAG 프로젝트에서 “DB가 정상 저장되었는지”를 확인할 때 매우 중요한 함수
	•	RAG 파이프라인 디버깅 시 필수

✔ 2-2. collection.count() — DB에 저장된 문서 수 확인

VectorDB에 데이터가 제대로 들어갔는지 빠르게 확인하는 방법.

실전에서는 다음 상황에 중요함:

	•	크롤링 → 전처리 → Chunking 후 문서 수 검증
	•	문서 누락 여부 확인
	•	배포 환경에서 VectorDB Health 체크

✔ 2-3. collection.get(ids=[...]) — ID 기반 문서 조회

rag03에서 중요한 포인트는 ID 기반 직접 조회 기능을 처음 다룬다는 점이다.

왜 중요한가?

•	Retrieval 기반 검색 외에도 “특정 문서 직접 접근”이 가능해야 PDF 분해, 웹 문서 수집, 섹션 기반 RAG 구성 시 활용 가능
•	VectorDB를 단순 검색기(Search Engine)가 아닌 데이터 저장소(Database)로 활용하는 시각을 제공한다.

## 📚 3. ChromaDB 검색 결과 구조 (2D Document Matrix)

rag03에서는 다음 코드가 등장한다:

```python
results["documents"][0]
context = "\n".join(results["documents"][0])

이것은 ChromaDB의 검색 결과가 다음과 같은 형태이기 때문이다:

documents = [
    ["문장1", "문장2", "문장3"]
]
```
문서 구조가 2차원 배열이다.

| 차원  | 의미                   |
| --- | -------------------- |
| 1차원 | 여러 쿼리(batch)         |
| 2차원 | 각 쿼리에 대한 top-k 검색 결과 |

왜 이것이 중요한가?

	•	rag02에서는 단일 문서 리스트처럼 다뤘지만
	•	실제 VectorDB는 쿼리 개수(batch) 에 따라 구조가 달라짐
	•	향후 rag10_routing, rag11_async에서 batch query를 학습할 때 필수 개념

## 🧠 4. Prompt Engineering for RAG (고급 기법)

프롬프트 엔지니어링 심화 단계

프롬프트 예시:
```python
아래 정보를 참고해서 친절한 답을 해줘.
가능하면 예시나 배경지식도 알려줘.
정보:
{context}

질문:
{query}
```

추가사항: 마크업은 반드시 빼줘.

여기서 중요한 개념은 다음 4가지입니다.

✔ 4-1. Retrieval-Conditioned Prompting

검색된 문서(context)를 LLM의 입력으로 제공하여
정확성과 신뢰도를 높이는 Prompt 구조.

👉 [참고 - 텍스트 기반 RAG 이론 : Prompt Augmentation￼](90.course_notes/00.NOTES/251205_rag.md)

✔ 4-2. 출력 스타일 제어 (Stylistic Constraints)

모델에게 다음을 지시한다:

	•	예시 제공
	•	배경지식 추가
	•	친절한 말투
	•	마크다운 금지

이는 실전 RAG 챗봇에서 매우 중요한 엔지니어링 기술이다.

- 예시: 마크다운 금지

코드 블록이나 **강조**가 섞이면 UI 파싱이 어려운 환경에서 문제가 생긴다.

✔ 4-3. 문맥 기반 생성 (Context-Aware Generation)

LLM이 답변을 생성할 때, 지식의 출처는 다음 두 가지다:
	1.	학습된 내부 지식
	2.	검색된 Retrieval 문서

rag03은 (2)의 비중을 높이기 위해
문맥을 명시적으로 강화하는 기법을 사용한다.

✔ 4-4. 잘못된 정보 보완 & 환각 억제

“예시 + 배경지식 제공” 요청은
LLM이 문맥 기반으로 더 정교한 reasoning을 하도록 유도한다.

실전에서는 RAG 환각 억제의 핵심 기법 중 하나이다.
